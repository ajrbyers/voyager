Tag picker

Use a tag picker to search for and select several related items, such as keywords or subject categories. Selected items appear above the search field and can be removed individually.

The component uses HTMX to request results and update selections. Your application supplies the search, add, and remove endpoints.

Empty

With no items selected, the row of selected items shows a muted empty-state message instead.

Open with results

The search endpoint returns the results partial: matching items first, then a highlighted "Create" action when the query does not exactly match an existing item. When nothing matches and creation is not allowed, the partial shows a no-matches message.

{% set src %}{% raw %}{% from "voyager/components/tag-picker/tag-picker.j2" import tag_picker_results %} {# Rendered by the search view and returned as the response #} {{ tag_picker_results( name="subjects", q="Star", results=[ {"id": 12, "name": "Star formation"}, {"id": 14, "name": "Stellar evolution"}, ], add_url="/subjects/add/", can_create=True) }}{% endraw %}{% endset %} {{ example(src) }}

Required endpoints

The widget expects three endpoints:

  • Search - GET with a q parameter. Returns the tag_picker_results() partial, which HTMX swaps into the .tag-picker-results container. Triggered on input changed delay:200ms and on focus.
  • Add - POST with either item_id (an existing item) or name (create a new item, then add it). Returns the full tag_picker() widget, swapped via outerHTML.
  • Remove - POST per item (each selected item carries its own remove_url). Also returns the full widget.

Notes

  • The whole widget (#tag-picker-{name}) is the swap target for add and remove, so the selected items, empty state, and results all stay consistent after every operation.
  • Only offer the create action (can_create=True) when the query does not case-insensitively match an existing item, and validate creation on the server regardless.
  • Each remove button carries an aria-label naming the item ("Remove Astrophysics") so screen readers announce what is being removed.
  • The tagPicker driver in the JavaScript bundle restores focus to the search input after each add or remove swap, because the whole widget is replaced. It announces "item added" or "item removed" through a visually-hidden aria-live region it keeps beside the widget.
  • The driver responds only to the picker's own swap, so an unrelated swap elsewhere on the page does not move focus or announce anything. If a request fails, it clears the pending action.
  • Users can reach result buttons with Tab from the search input. Arrow-key navigation is not supported.
  • This component requires JavaScript and HTMX. If the form must work without JavaScript, provide a working alternative such as a <select multiple> field, and handle its submission on the server.
  • The search input reuses .form-input from the form component - place the widget inside a .form-group with a .form-label in a form.
