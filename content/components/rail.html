Rail

Use the rail to place status, workflow steps, and related actions beside the main content on a detail page. See the peer review example for a rail in a complete page.

Rail sections

Divide the rail into short, named sections such as Status, Steps, and Actions. The rail is an <aside> of stacked .rail-section blocks, each introduced by an underlined <h2>. A status section usually holds an inset text block, and the others hold a steps list and an action menu.

Pairing with .layout-with-rail

The rail does not position itself - it relies on the .layout-with-rail utility, a two-column grid inside .app-shell-main (see Application shell). The main content takes the flexible left column; the rail takes a fixed right column sized by the --shell-rail-width token. Below 1100px the grid collapses to one column and rails render in markup order. Markup order is the priority control: a rail placed first inside layout-with-rail stays first in reading and tab order at every width - the grid still draws it as the right-hand column on wide screens - so put essential status and actions in a leading rail. A second, trailing rail after the content holds secondary sections and stacks beneath the leading one in the same column on wide screens. Don't reorder rails with CSS (order or grid placement alone): that changes only the visual position, leaving keyboard and screen-reader order behind.

When to use

  • Use the rail on detail screens, such as a single article, a review assignment, or a production task, where status and actions belong beside the content.
  • Use a full-width layout on list and dashboard screens, and put actions on the items themselves.
  • Keep the rail focused on information and actions relevant to the current task. Move detailed explanations into the main content.

Notes

  • The rail is an <aside> with an aria-label describing its contents (e.g. "Status, steps and actions") so screen-reader users can identify and skip the complementary landmark.
  • Section headings are <h2> elements - slot them into the page's heading hierarchy rather than skipping levels.
  • Markup order decides reading and keyboard order. Place a rail carrying essential status and actions before the main content, and a rail carrying secondary sections after it.
  • Put the page's main action, such as Make a decision, in the status section, above the steps and secondary actions.
