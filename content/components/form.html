Form

Every field type shares one structure: group wrapper, label, hint, error message, control. Voyager's form conventions: mark optional fields (never required), error messages use <p> with a visually-hidden “Error:” prefix, error groups get a red left border, aria-describedby lists the hint first then the error, and radio/checkbox controls are 40 × 40 px.

Text input

Optional fields append “(optional)” to the label. Don't mark required fields - treat every field as required unless its label says otherwise.

Width modifiers

Fixed character widths on inputs that should be sized to their content (postcodes, reference numbers, dates).

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_text %} {{ form_text( name="postcode", id="postcode", label="Postcode", width=10, autocomplete="postal-code" ) }}{% endraw %}{% endset %} {{ example(src) }}

Available: form-input-width-2, -3, -4, -5, -10, -20. For fluid widths use form-width-full, form-width-three-quarters, form-width-two-thirds, form-width-one-half, form-width-one-third, form-width-one-quarter.

Textarea with character count

The character-count wrapper sits outside the form-group; the count message is a sibling div with an id referenced by the textarea's aria-describedby. Order in aria-describedby: count message id, then hint, then error.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_textarea_with_count %} {{ form_textarea_with_count( name="letter", id="letter", label="Decision letter", maxlength=4000 ) }}{% endraw %}{% endset %} {{ example(src) }}

Radios

40 × 40 px controls - comfortably past the WCAG 2.2 minimum touch-target size. Group inside a fieldset; the legend is the question. For small dense radio rows compose form-radio-small.

Date input

Three numeric text inputs (day, month, year) inside a fieldset with role="group". Day and month use form-input-width-2; year uses form-input-width-4. inputmode="numeric" brings up the numeric keypad on mobile.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_date %} {{ form_date( name="due", id="due", legend="Due date", hint="For example, 27 5 2026" ) }}{% endraw %}{% endset %} {{ example(src) }}

Error state

Three things change in an error state:

  1. Add form-group-error to the wrapping form-group - gives the red left border + padding.
  2. Add the error message as a <p class="form-error-message"> with a visually-hidden “Error:” prefix span.
  3. Add form-input-error (or form-textarea-error / form-select-error) to the control. Set aria-describedby to include the error id. If a hint is also present, hint id comes first, then error id.
{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_text %} {{ form_text( name="due", id="due", label="Due date", type="date", error="Enter a date in the future" ) }}{% endraw %}{% endset %} {{ example(src) }}

Password input

Password field with a Show / Hide toggle. The toggle is a sibling button; a small JS handler swaps the input's type attribute between password and text. aria-controls ties the button to the input it controls.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_password %} {{ form_password( name="password", id="password", label="Password", hint="Use at least 12 characters, mixing letters, numbers and symbols", autocomplete="new-password" ) }}{% endraw %}{% endset %} {{ example(src) }}

Tiny driver - wire once at page level:

{% set src %}{% raw %}document.addEventListener('click', function (event) { var btn = event.target.closest('[data-form-password-toggle]'); if (!btn) return; var id = btn.getAttribute('aria-controls'); var input = document.getElementById(id); if (!input) return; var showing = input.type === 'text'; input.type = showing ? 'password' : 'text'; btn.textContent = showing ? 'Show' : 'Hide'; });{% endraw %}{% endset %} {{ example(src, jinja=False) }}

Heading-as-label / heading-as-legend

When a form has a single question, that question is the page heading: wrap the label in an <h1> (single-input forms) or wrap an <h1> inside the legend (multi-input). The visual heading and the form label are the same element - announced once.

Notes

  • Pair errors with an error summary at the top of the form. Each summary entry is a link that focuses the field.
  • Don't use placeholder text as a substitute for a label or hint.
  • Don't disable submit buttons while errors exist - let the user submit and see the error summary.
  • Group questions logically; one question per page where possible - each step stays focused and error recovery stays simple.
