Form

Voyager's form controls use a consistent arrangement of labels, hints, and error messages. Mark optional fields with (optional) and explain errors beside the affected controls.

Text input

Every field type shares one structure: a group wrapper, a label, a hint, an error message, and the control itself. Optional fields append "(optional)" to the label. Treat every field without that marking as required.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_text %} {{ form_text( name="full_name", id="full-name", label="Full name", optional=True, hint="Enter your name as you want it to appear on the published article" ) }}{% endraw %}{% endset %} {{ example(src) }}

Width modifiers

Match the field width to the expected answer. Short identifiers and dates need less space than names or email addresses.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_text %} {{ form_text( name="postcode", id="postcode", label="Postcode", width=10, autocomplete="postal-code" ) }}{% endraw %}{% endset %} {{ example(src) }}

Available: form-input-width-2, -3, -4, -5, -10, -20. For fluid widths use form-width-full, form-width-three-quarters, form-width-two-thirds, form-width-one-half, form-width-one-third, form-width-one-quarter.

Textarea with character count

Use a character count when an answer has a length limit. As the user types, Voyager updates the remaining count and announces it after a short pause through a visually-hidden aria-live region.

Without JavaScript, the static "You can enter up to N characters" message and the native maxlength limit still apply.

The character-count wrapper sits outside the form-group. The count message is a sibling div with an id referenced by the textarea's aria-describedby, in this order: count message id, then hint, then error.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_textarea_with_count %} {{ form_textarea_with_count( name="letter", id="letter", label="Decision letter", maxlength=4000 ) }}{% endraw %}{% endset %} {{ example(src) }}

Radio buttons

Use radio buttons when the user must choose one option. Group the options in a fieldset and use its legend for the question.

The controls are 40 × 40 px, which meets the WCAG 2.2 minimum touch-target size. Use form-radio-small for dense radio rows.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_radios, form_radio %} {% call form_radios("decision", "What is your decision?") %} {{ form_radio("decision", "accept", "Accept submission", hint="Move to the next workflow stage.") }} {{ form_radio("decision", "minor", "Request minor revisions", hint="Author addresses small changes.", checked=True) }} {{ form_radio("decision", "reject", "Reject submission") }} {% endcall %}{% endraw %}{% endset %} {{ example(src) }}

Date input

Three numeric text inputs (day, month, year) sit inside a fieldset with role="group". Day and month use form-input-width-2; year uses form-input-width-4. inputmode="numeric" brings up the numeric keypad on mobile.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_date %} {{ form_date( name="due", id="due", legend="Due date", hint="For example, 27 5 2026" ) }}{% endraw %}{% endset %} {{ example(src) }}

Error state

Three things change in an error state:

  1. Add form-group-error to the wrapping form-group, which adds the red left border and padding.
  2. Add the error message as a <p class="form-error-message"> with a visually-hidden "Error:" prefix span.
  3. Add form-input-error (or form-textarea-error / form-select-error) to the control. Set aria-describedby to include the error id. If a hint is also present, the hint id comes first, then the error id.
{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_text %} {{ form_text( name="due", id="due", label="Due date", type="date", error="Enter a date in the future" ) }}{% endraw %}{% endset %} {{ example(src) }}

Password input

The password field includes a Show button so users can check what they have entered. Selecting it again hides the password.

This behaviour comes from Voyager's JavaScript entry point, voyager/assets/js/index.js, so no page-level handler is needed. aria-controls ties the button to the input it controls.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_password %} {{ form_password( name="password", id="password", label="Password", autocomplete="new-password" ) }}{% endraw %}{% endset %} {{ example(src) }}

File upload

The native file input is styled to match the other form controls. Use accept to suggest file types in the file chooser. Validate the uploaded file on the server. Pass multiple=True when users can select more than one file.

The size limit in this example is application policy. The macro does not enforce it.

{% set src %}{% raw %}{% from "voyager/components/form/form.j2" import form_file %} {{ form_file( name="manuscript", id="manuscript", label="Manuscript", hint="Upload a DOCX, PDF, or TEX file up to 25 MB.", accept=".docx,.pdf,.tex" ) }} {{ form_file( name="figures", id="figures", label="Figures", optional=True, multiple=True ) }}{% endraw %}{% endset %} {{ example(src) }}

Using the question as the page heading

When a form asks a single question, use that question as the page heading. Wrap the label in an <h1> for a single-input form, or wrap an <h1> inside the legend for a multi-input form. The question text serves as both the page heading and the label for the input or group of inputs.

{% set src %}{% raw %}

The 16-digit identifier on your ORCID profile, for example 0000-0002-1825-0097.
{% endraw %}{% endset %} {{ example(src, jinja=False) }}

Notes

  • Pair errors with an error summary at the top of the form. Each summary entry is a link that focuses the field.
  • Do not use placeholder text as a substitute for a label or hint.
  • Do not disable submit buttons while errors exist. Let the user submit and see the error summary.
  • Group questions logically, with one question per page where possible, so that each step stays focused and error recovery stays simple.
