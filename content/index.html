Voyager

Voyager is Janeway's design system.

Design principles

Components are built to be as accessible as possible. Where a good pattern already exists, we opt to use it and many here are adapted from the GOV.UK Design System.

How it's organised

  • Foundations - the tokens, type scale, and layout primitives that everything else builds on.
  • Components - self-contained patterns. Each component pairs a .css file with a .j2 macro. The CSS uses a single root class with native nesting; variants compose as additional flat classes.
  • Examples - three reference pages showing Voyager's components composed into real Janeway screens: the editor dashboard, the manager index, and the peer-review screen. The component markup is currently handwritten (not rendered through the macros) and each page adds its own page-level layout styles.

How to use it

Add one stylesheet to your page and use the component HTML or call the Jinja2 macros:

{% set src %}{% raw %}{% from "voyager/components/tag/tag.j2" import tag %} {{ tag("Under review", kind="green") }} {{ tag("Article", kind="grey") }}{% endraw %}{% endset %} {{ example(src) }}

Architecture

Voyager follows the Memory Alpha CSS approach: layer order (settings → reset → elements → components → utilities), single root class per component, native CSS nesting, composable variant classes (no BEM), two-tier tokens (raw + semantic). See the Architecture page for the full picture.
