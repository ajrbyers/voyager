Usage guidance

Use this guidance to choose components and arrange them around an editorial task.

Choosing a container

Four components overlap as a box with a heading. Choose by what the content is:

  • Summary block - show related facts about an article, person, or task. Use summary-list rows for labels, values, and actions such as Change.
  • Queue card - link to a workflow queue and show its submission counts.
  • Article card - show one submission in a list, with its title, status, and available actions.
  • Panel - confirm the outcome of an action, such as a submitted review or an editorial decision.

Failures, unsaved work, and blocked workflows

  • Failed actions. If an action fails, explain what happened and what the user can do next. Place the message near the affected content. For form errors, show a message beside each affected field and an error summary above the form.
  • Unsaved work. Before an action discards unsaved work, explain what will be lost. Place the warning beside the action.
  • Blocked workflows. If an action is unavailable, explain what must happen first. Place the available actions that help resolve the problem beside that explanation. In Voyager, the blocked action renders as an inert placeholder (btn is-disabled with aria-disabled="true") and the resolving actions are listed first; the peer-review reference page shows this in its status rail.
  • Emphasis. Use the primary button for the page's main action. Give routine information less emphasis so that warnings and required actions are easy to find.

Density

Compact text suits repeated information such as submission metadata, counts, and status labels. Use larger text for instructions, review reports, decision letters, and other content that needs sustained reading.

Keep uppercase labels short. Write instructions in sentence case.

Narrow screens

Keep essential status and actions close to the content they concern, and check the visual order, reading order, and keyboard order when the layout changes. In Voyager this is decided by markup order: below 1100px, layout-with-rail collapses to one column and everything renders in document order. Put the page's essential status and actions in a rail placed first inside the layout, as on the peer-review screen - it leads the reading and tab order at every width, and the grid draws it as the right-hand column on wide screens. Put secondary sections in a trailing rail after the content. Do not reorder content with CSS alone: order and grid placement move the visual position without changing the reading or keyboard order.
