Layout

Janeway pages share a common shell - top header, left sidebar, main column - and a small set of inner layouts. Use the shell components for the chrome and the layout utilities to arrange page content.

Page types

Each pairs a layout with the Nielsen Norman Group usability heuristics it is built to serve - the layout is not decoration; it is how the page keeps the editor oriented and in control. Inbox / triage

Full-width, no rail: a folder-list on the left, a sticky toolbar, and a severity-grouped list of article-cards. Reference: dashboard example.

  • Visibility of system status - folder counts and critical / warning grouping surface the size and urgency of every queue before the editor opens anything.
  • Recognition rather than recall - each queue and saved folder is a visible, clickable target, so nothing has to be remembered or re-typed between visits.
  • Flexibility and efficiency of use - sort controls and custom saved folders are accelerators for editors who work this list many times a day.
  • Aesthetic and minimalist design - the rail is dropped so the full width belongs to work items; every row is a live piece of work.

Index / launcher

Full-width layout-full with a filter bar over a sectioned grid of function-cards. Reference: manager example.

  • Recognition rather than recall - the whole page is a visible directory of every function, grouped by domain, so editors scan and choose instead of recalling where a tool lives.
  • Flexibility and efficiency of use - a search field and category filter let a returning user jump straight to a known function without scrolling the full index.
  • Consistency and standards - a uniform card grid means every function looks and behaves the same, so a new card needs no new learning.
  • Match between system and the real world - sections are named for the editorial domains (Review, Submission, Identifiers) rather than the code that implements them.

Work / detail

layout-with-rail: readable content on the left, a rail on the right carrying status, steps, and actions. Reference: peer-review example.

  • Visibility of system status - the rail's Status and Steps show exactly where the article sits in the workflow and what is blocking the next move, without scrolling the content.
  • User control and freedom - the primary decision and the reversible actions live in the rail, always in reach and clearly separated from the material being read.
  • Error prevention - a notice block flags overdue revisions and unacknowledged reviewers above the content, so the editor sees the risks before making a decision.
  • Match between system and the real world - the breadcrumb and review-round tabs mirror the real editorial process rather than the database behind it.

Grid utilities

Equal-column grids for cards and tiles: .grid .grid-2, .grid-3, .grid-4. They collapse to a single column under 900px.

Spacing primitives

Two layout primitives in utilities.css:

  • .stack - vertical rhythm. Adds margin-top to every direct child after the first. Variants: .stack-sm, .stack-lg, .stack-xl.
  • .cluster - horizontal flex group with gap and wrap. Variants: .cluster-sm, .cluster-lg.

Breakpoints

Voyager uses three breakpoints, all max-width:

  • 900px - sidebar collapses to top, multi-column grids collapse to one.
  • 1100px - .layout-with-rail stacks the rail below main.
  • 600px - summary-list rows stack key/value/change vertically.
