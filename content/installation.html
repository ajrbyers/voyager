Installation

Voyager installs as a Django app. Installing it gives your project the stylesheet and JavaScript entry points and the Jinja macros.

Install the package

Install from the repository, or from a local checkout for live editing:

pip install git+https://github.com/openlibhums/voyager.git
# or, for live editing against a local checkout:
pip install -e ~/Code/voyager

Voyager requires Django 4.2 or later and Jinja2, both declared as dependencies of the package.

Add the app

Add voyager to INSTALLED_APPS:

INSTALLED_APPS = [
    # ...
    "voyager",
]

Link the entry points

collectstatic gathers the design system automatically. Link the two entry points with the static tag:

<link rel="stylesheet" href="{% raw %}{% static 'voyager/assets/css/index.css' %}{% endraw %}">
<script type="module" src="{% raw %}{% static 'voyager/assets/js/index.js' %}{% endraw %}"></script>

Render the macros

The Jinja macros ship in the app's jinja2/ directory. A Jinja2 template backend with APP_DIRS: True resolves the voyager/components/... import paths with no further configuration:

TEMPLATES = [
    {
        "BACKEND": "django.template.backends.jinja2.Jinja2",
        "DIRS": [],
        "APP_DIRS": True,
        "OPTIONS": {},
    },
    # ... your Django template backend ...
]
{% raw %}{% from "voyager/components/tag/tag.j2" import tag %}

{{ tag("Under review", kind="green") }}{% endraw %}

Cache-busting in production

Point the staticfiles backend at Voyager's storage class:

STORAGES = {
    "staticfiles": {
        "BACKEND": "voyager.storage.VoyagerManifestStaticFilesStorage",
    },
}

Django's default ManifestStaticFilesStorage hashes and rewrites the @import chain in index.css but leaves the ES-module import specifiers in index.js untouched, so the component drivers would ship unhashed. VoyagerManifestStaticFilesStorage enables support_js_module_import_aggregation, so the JavaScript import chain is hashed in the same way as the CSS.
