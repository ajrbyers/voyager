Details

Collapsible disclosure block, GDS-inspired. Wraps the native <details>/<summary> elements so it works without JavaScript. Use sparingly - hidden content can be missed. Good for secondary help text, advanced options, or long file lists.

Remembers open state

Add data-details-persist="<key>" to opt in to localStorage persistence. The first visit respects the server-rendered state; after that, the last toggle by this user wins. The state is stored under voyager-details:<key>. Pick a key that is unique to the disclosure's purpose - same key on two pages will share state.

Toggle me, then reload

The next page load will reopen this block if you left it open, or keep it closed if you closed it. Try it.

<details class="details" data-details-persist="peer-review-r419">
  <summary>Details</summary>
  <div class="details-body"> … </div>
</details>

Notes

  • Use <details> - never roll your own collapsible. Keyboard and screen-reader support is free.
  • The summary should describe what's inside, not "Show more". A user should know whether to click without trying.
  • Don't hide critical content. If a user must see it to complete a task, don't put it inside details.
  • Persist (data-details-persist) is for long-lived disclosures such as file lists or expanded panels - not for help text, validation messages, or anything that should reset on each page-load.
