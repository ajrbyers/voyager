Application shell

The page-level layout for admin screens: a two-column grid with the sidebar nav on the left and the page content on the right, finished with a modest app footer. The app header sits above the shell, not inside it.

App shell

Place .app-shell directly inside <body>, after the app header. The first child is the sidebar nav; the second is <main class="app-shell-main">, which holds the page content. The grid collapses to a single column below 900px. The main column has no padding of its own - use a layout utility such as .layout-full or .layout-with-rail (see the Rail page) to space the content. See the peer review example for the shell in full context.

When to use

  • Use the app shell on every signed-in admin screen - dashboards, workflow pages, manager pages.
  • Don't use it on public-facing or reading pages; those have their own layouts.
  • One shell per page. Nesting shells or adding extra columns at this level breaks the responsive collapse - use .layout-with-rail inside the main column instead.

Notes

  • The app header is a sibling above the shell, not a child of it - the shell's min-height is calculated against the header's height. It is documented on the App header page.
  • Give .app-shell-main the id="main" so the skip link has a target.
  • The sidebar column width comes from the --shell-sidebar-width token; override it at the page level only if a screen genuinely needs a wider nav.
  • The footer strip at the base of the main column is documented on the App footer page.
